# 校园体育赛事助手 - 测试报告

## 一、后端 API 功能测试

**测试内容**：使用 Jest + supertest 对后端 Express 接口进行功能回归测试。覆盖健康检查、赛程列表、积分榜、球员榜四个核心接口，验证 HTTP 状态码、响应结构、关键字段（如 `home_team_name`、`away_team_name`、`team_name`、`player_name`）的正确性，确保接口返回的数据结构完整且符合前端需求。

**编写方法**：在 `PKU_CSports_backend/tests/api.test.js` 中，使用 `supertest` 直接挂载 Express 应用（不启动真实端口），通过 `request(app).get()` 发起请求，用 Jest 的 `expect` 断言状态码、`success` 字段和数据结构。测试依赖 `scripts/seed.js` 预置的测试数据，确保可重复执行。

**所用框架**：Jest（测试运行器与断言库）、supertest（HTTP 断言库）。

**最终结果**：4 个用例全部通过，验证了接口返回正确状态码、数据结构完整，以及联表查询返回球队/球员名称字段，为前端数据展示提供了可靠保障。

**测试内容**：对登录接口 `/api/auth/login` 进行全面的功能测试，包括参数验证（空用户名/密码）、错误密码处理、成功登录场景，以及不同角色用户（普通用户、协会用户）的登录验证。确保认证流程的健壮性和安全性。

**编写方法**：在 `PKU_CSports_backend/tests/api/auth.test.js` 中，使用 supertest 发送 POST 请求，测试各种输入场景。验证成功登录时返回的 token 和用户信息结构，确保角色字段正确返回。

**所用框架**：Jest、supertest。

**最终结果**：4 个测试用例全部通过，验证了登录接口的参数校验、错误处理和成功场景，确保不同角色用户都能正确登录并获得相应权限。

## 三、后端权限控制测试

**测试内容**：对赛程接口的权限控制进行测试，验证未认证请求、普通用户和协会用户对敏感操作（如更新比分）的访问权限。确保系统的安全性和角色权限的正确实现。

**编写方法**：在 `PKU_CSports_backend/tests/api/matches-auth.test.js` 中，使用 JWT 生成不同角色的 token，测试 `/api/matches/:id/result` 接口在不同权限下的响应。验证未认证返回 401，普通用户返回 403，协会用户允许访问。

**所用框架**：Jest、supertest、jsonwebtoken。

**最终结果**：3 个测试用例全部通过，验证了权限中间件正确工作，普通用户无法执行协会专属操作，系统安全性得到保障。

**所用框架**：Jest。

**最终结果**：3 个测试用例全部通过，验证了密码工具函数能够正确生成唯一哈希值、准确验证密码，为系统安全提供了基础保障。

## 七、后端性能测试 - 积分榜接口

**测试内容**：使用 k6 对积分榜和球员榜接口进行性能测试，模拟 15 个虚拟用户持续 30 秒的并发请求，验证接口在负载下的响应时间和成功率。

**编写方法**：在 `PKU_CSports_backend/tests/perf/standings.k6.js` 中，配置 `vus: 15` 和 `duration: '30s'`，设置性能阈值 `http_req_duration: ['p(95)<500']`（95% 的请求响应时间应小于 500 毫秒）。测试积分榜和球员榜两个接口，验证状态码和响应体内容。

**所用框架**：k6（性能与压力测试工具）。

**最终结果**：测试通过，95% 的请求响应时间在 500 毫秒以内，接口在 15 并发下表现稳定，满足性能要求。

## 九、后端压力测试

**测试内容**：对系统进行阶梯式压力测试，模拟负载从 20 用户逐步增加到 100 用户，然后逐步降回 0，验证系统在高负载下的稳定性和性能表现。

**编写方法**：在 `PKU_CSports_backend/tests/perf/stress.k6.js` 中，使用 k6 的 `stages` 配置阶梯式负载增长：30 秒内增加到 20 用户，1 分钟内增加到 50 用户，30 秒内增加到 100 用户，保持 1 分钟后逐步降回 0。随机访问赛程、积分榜、新闻三个接口，设置性能阈值（95% 请求 < 1 秒，错误率 < 5%）。

**所用框架**：k6、自定义错误率指标。

**最终结果**：测试通过，系统在 100 并发下仍能保持稳定，95% 的请求响应时间在 1 秒以内，错误率低于 5%，系统具备良好的抗压能力。

**所用框架**：Vitest（测试运行器）、@vue/test-utils（Vue 组件测试工具，本用例主要用于工具函数测试）。

## 十二、前端界面端到端测试 - 赛事页面

**所用框架**：Cypress（端到端测试框架）。

**最终结果**：测试通过，验证了前端页面能正确加载数据并渲染 UI，确保了用户可见功能的正确性。
