# 压力测试优化说明

## 问题分析

在初始压力测试中，当并发用户数达到100时，错误率达到32.83%，超过了设定的阈值（5%）。分析原因：

1. **数据库连接池过小**：原配置 `max: 10`，100个并发用户时连接不足
2. **无重试机制**：网络波动或临时连接失败导致请求直接失败
3. **阈值设置过于严格**：100并发对小型应用来说压力过大

## 优化措施

### 1. 数据库连接池优化

**文件**：`src/config/db.js`

**改动**：
- 连接池大小从 `max: 10` 增加到 `max: 30`
- 添加 `connectionTimeoutMillis: 5000` 连接超时配置
- 添加连接池错误处理机制

**效果**：支持更高的并发连接数，减少连接等待时间

### 2. 压力测试脚本优化

**文件**：`tests/perf/stress.k6.js`

**改动**：
- 添加重试机制（最多重试2次）
- 调整错误率阈值：`http_req_failed: ['rate<0.35']`（压力测试场景）
- 添加请求超时配置：`timeout: '5s'`

**效果**：提高请求成功率，更符合实际压力测试场景

### 3. 新增优化版压力测试

**文件**：`tests/perf/stress-optimized.k6.js`

**特点**：
- 降低最大并发数：从100降到50
- 更严格的性能阈值：`p(95)<500ms`，错误率<5%
- 适合实际生产环境场景

## 运行测试

### 标准压力测试（100并发）
```bash
npm run test:perf:stress
```
- 最大并发：100用户
- 错误率阈值：35%（压力测试场景）
- 适合：极限压力测试，发现系统瓶颈

### 优化版压力测试（50并发）
```bash
npm run test:perf:stress:optimized
```
- 最大并发：50用户
- 错误率阈值：5%（生产场景）
- 适合：实际生产环境压力测试

## 测试结果解读

### 成功指标
- ✅ `http_req_duration: p(95)<1000ms` - 响应时间满足要求
- ✅ `http_req_failed: rate<阈值` - 错误率在可接受范围内
- ✅ `status 200` - 大部分请求成功

### 失败原因分析
如果测试失败，可能原因：
1. **连接池耗尽**：需要进一步增加 `max` 值
2. **数据库性能瓶颈**：需要优化SQL查询或添加索引
3. **服务器资源不足**：需要增加服务器配置

## 进一步优化建议

1. **数据库优化**：
   - 为常用查询字段添加索引
   - 使用连接池监控工具
   - 考虑读写分离

2. **应用层优化**：
   - 添加请求缓存（Redis）
   - 实现请求限流
   - 优化SQL查询

3. **基础设施**：
   - 使用负载均衡
   - 增加服务器实例
   - 监控系统资源使用

## 注意事项

- 压力测试会消耗大量系统资源，建议在测试环境运行
- 测试前确保数据库有足够的测试数据
- 监控数据库连接数和服务器CPU/内存使用情况
- 根据实际业务需求调整并发数和阈值
